# Story 7.1 — Mirrored seeds and side swaps

As a reader of the leaderboard, I want every pairing played from both sides of every seed, so that a side advantage in the game cannot masquerade as a skill difference.

## Acceptance criteria

**Given** a pairing and a seed, **When** the tournament schedules it, **Then** exactly two Matches exist with the agents in opposite array positions and distinct `matchId`s.

**Given** any Command Log, **When** inspected, **Then** array index 0 is always P1 — there is no "sides swapped" flag.

**Given** a pairing with fewer than **30 Matches** (15 seeds × 2 sides), **When** the leaderboard is generated, **Then** it is shown as provisional and not rated.

**Given** results, **When** they are published, **Then** any side advantage in the Environment is measurable from them and reported.

## Scope

Tournament scheduling and the side-advantage report.

## Frozen contracts touched

None modified.

## Invariants at risk

- **INV-2** — a mirrored pair that disagrees beyond genuine side asymmetry indicates non-determinism.

## Architecture decisions that constrain this

- **AD-12** — a side swap is a separate Match, never a boolean.

## Test plan

Pairing enumeration produces exactly two Matches per seed with correct positions. Provisional labelling below 30 Matches. Side-advantage computation against synthetic biased data.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.
