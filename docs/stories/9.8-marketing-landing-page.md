# Story 9.8 — Marketing landing page

As a visitor with no context, I want to land on a page that pitches the project, shows it in motion, and lets me play, so that I decide this is worth thirty seconds before I've read a word.

**Capstone of Epic 9** — the first story here whose exit gate is a user journey, not only an engineering fact, per the roundtable finding this epic's plan already recorded: an epic about visitors needs at least one visitor-observable check.

## Acceptance criteria

**Given** a visitor, **When** the page loads, **Then** they see, before scrolling: the project's pitch, a looping carousel of pre-recorded fight-clip snippets, entry points into Play-vs-CPU (Story 9.2) and Spectate (Story 9.3), and the leaderboard (Epic 7).

**Given** the clip carousel, **When** built, **Then** it is a fixed, curated set of short recordings, manually produced and committed as static video assets — not an automatically growing archive, and not live-rendered canvas.

**Given** the page, **When** it loads, **Then** only static hosting is used — no upload pipeline, no per-visitor recording, no server call to build the page. Validates INV-8.

**Given** UJ-5 (a visitor lands, clicks Play, is fighting within seconds, no key, no signup), **When** walked through directly — via the Chrome DevTools MCP, live, not inferred from the engineering checks above — **Then** it holds true end to end. This is the check the room's UX voice insisted on: passing every other AC here and still not delivering UJ-5 is a failed story.

**Given** the page's layout, **When** designed, **Then** it references LM Arena's leaderboard-first information hierarchy only — no LM Arena code, text, or assets used anywhere.

## Scope

`apps/web`: the landing page itself, curated video clip assets under `apps/web/public`, wiring to the existing Arcade (9.2), Spectate (9.3), and leaderboard (Epic 7) entry points. No new backend of any kind.

## Frozen contracts touched

None.

## Invariants at risk

- **INV-8** — static hosting only; checked directly against this story's network activity, not assumed.

## Architecture decisions that constrain this

- **AD-15** — landing-page presentation code stays in `apps/web`.
- **AD-17** — the carousel embedded here is the same manifest-walk principle Story 9.3 established, applied to marketing clips instead of full Matches.

## Test plan

Time-to-first-meaningful-content check on a simulated slow connection, same discipline as Story 4.2's 2-second budget. Live UJ-5 walkthrough via the Chrome DevTools MCP: land, click Play, confirm a fight is running, with no key and no signup at any point. Asset-budget check confirming the clip carousel's total size stays within a static-hosting-appropriate budget (the exact count/duration was deliberately left to this story per PRD `OQ-10` — decide it here, within the INV-8 constraint, not before).

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero **AND** the live UJ-5 walkthrough passing **AND** the time-to-content budget met.
