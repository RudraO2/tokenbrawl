# Story 1.4 — The replay determinism gate

As the developer, I want replay proven bit-identical before anything else is built, so that a one-in-fifty non-determinism bug is caught now rather than at E7.

## Acceptance criteria

**Given** a fixture Command Log, **When** it is replayed 100 consecutive times in one process, **Then** every Final-State Hash matches the recorded value. Zero flakes.

**Given** the same fixture, **When** it is replayed in 100 **separate processes**, **Then** every hash still matches. Same-process-only testing hides global-state leakage and does not satisfy this story.

**Given** a deliberately mutated action in the log, **When** replayed, **Then** the hash differs — proving the test can actually fail.

## Scope

Replay path in `packages/core`, plus the determinism test suite. This story is the reason E1 exists, and **it blocks every downstream epic**.

If it cannot be made to pass, do not proceed and do not weaken the test. Escalate.

## Frozen contracts touched

None modified.

## Invariants at risk

- **INV-2** — this story *is* INV-2.

## Architecture decisions that constrain this

- **AD-5** — integers only, fixed timestep, PRNG threaded through state rather than module-global, deterministic iteration order.
- **AD-8** — one hash function over a canonical serialisation.

## Test plan

100 in-process replays. 100 cross-process replays, spawning a child process per run. A negative test proving the harness detects a planted divergence.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**. Never widen a frozen interface.
