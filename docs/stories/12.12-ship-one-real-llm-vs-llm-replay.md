# Story 12.12 — Ship one real fight between two language models

As a visitor, I want the flagship replay to be two actual language models fighting with their real reasoning attached, so that the thing this project is *for* is on the screen instead of two Baseline Bots standing in for it.

**This story was written to park at `awaiting-operator`, and it did not have to.** Its blocking input was a provider API key, and one was supplied to the session that implemented it — so the agent half and the operator half both ran in one pass and the status is `done`. Nothing was stubbed and no log was faked; the shipped replay is one real Match against Groq's live free-tier endpoint. What *is* still owed is recorded in `operator_actions_completed` above: **rotate the key**, because it reached this session through a chat transcript.

The rest of this section is left as written, because it is the reasoning that made the parking design correct and it stays correct for the next story shaped like this one.

## Why this is the last story in the epic

Everything above it makes the product look like an arcade fighter. This one makes it be what it claims to be.

The claim is on the page: *"language models fighting under a fixed token budget"* (`apps/web/index.html`'s description meta). What ships is a corpus of Baseline-Bot-versus-Baseline-Bot Matches. Every `decisions[]` entry in every committed log reads:

```json
{ "reasoning": null, "rawResponse": "random:advance", "provider": "bot", "endpoint": "bot" }
```

`reasoning: null` on every decision of every log. Story 4.3's hover reasoning is described in `docs/stories/README.md` as the **centrepiece feature**, and there is no committed replay in which it has anything to show. A visitor hovering a Decision Point today gets nothing, on the feature the project's own story queue calls its centre.

Everything needed to produce a real one already exists and is shipped: Story 3.1's Deployment Agent, Story 3.2's Groq adapter, Story 3.3's Cerebras and Google adapters, Story 3.4's metering probe, Story 3.5's provenance and prompt caching, Story 4.3's reasoning sidecar and Story 5.1's local CLI. Nothing here is new engineering. The missing input is a key.

## What the dev session does before parking

All of it, committed, so the operator's job is to run one command and review its output:

1. **A committed generator** — a script beside `apps/web/scripts/build-spectate-manifest.mts` that runs one Deployment-versus-Deployment Match through the existing CLI path, writes the Command Log and its reasoning sidecar into `apps/web/public/replays/`, and updates the manifest. Deterministic in everything except the model's own responses, which are recorded in the log and are what makes the replay a replay (INV-2: the Match is re-simulated from the log, never recorded).
2. **Free-tier only.** `assertFreeTierEndpoint` governs tournament configuration and is not loosened. INV-8 is zero recurring cost, and a free-tier Groq key satisfies it. The generator refuses a non-allowlisted endpoint rather than warning about one.
3. **Key hygiene, proven.** The key is read from the environment only (`packages/cli/src/config.ts` rejects a literal key in config and says so), never written to a file, never echoed. `scripts/assert-no-secret-leak.sh` and `packages/cli/src/secrets.test.ts` cover this and must pass over the generator and over its output.
4. **The failure path is written and tested first.** With no key present the generator exits with a clear message naming `GROQ_API_KEY` — which is the state it will actually be in when the dev session runs it, and therefore the only behaviour the dev session can verify end to end.
5. **The player is proven ready for the log it cannot yet produce**, against a fixture: a synthetic v2 log with a populated sidecar, asserting that hover reasoning renders real text, that `provider` and `endpoint` show on the Decision Point, that the Token Bank HUD draws a real budget, and that a Parse Failure in the corpus renders as a Parse Failure rather than as a gap. Every one of these paths ships untested against real data today.
6. **The rating exclusion is correct.** A single exhibition replay is not a tournament result. It must not enter the leaderboard by existing — `ratingEligibility` decides, and the story asserts the answer rather than assuming it.

## Acceptance criteria

Run against the fixture until the real log lands, and against the real log afterwards.

**Given** the fixture, **When** the Token Bank HUD draws, **Then** it shows a real budget rather than the empty meter a Baseline Bot produces. Same gate run.

Parse Failures are a first-class metric in `docs/INVARIANTS.md` and this is the only surface a visitor meets one on.

**Given** the shipped exhibition replay, **When** `ratingEligibility` is asked, **Then** it is excluded from the leaderboard, asserted rather than assumed.

**Given** a provider key **(operator)**, **When** the generator runs, **Then** it produces one v2 Command Log with real `provider`, `endpoint` and per-decision `reasoning`, plus its sidecar, and the log verifies its own Final-State Hash on replay.

**Given** that replay **(operator)**, **When** a visitor loads the site, **Then** it is the flagship replay the player opens on, and `reasoning-panel-shows-text` passes against real model output.

**Given** the repository at any point, **When** `scripts/assert-no-secret-leak.sh` runs, **Then** it passes. No key in a log, a sidecar, a manifest, a screenshot or a report.

## What shipped

One Match, against Groq's live free-tier endpoint: **`groq-gpt-oss-120b` vs `groq-gpt-oss-20b`, seed 121200, 57 Decision Points**, all 57 carrying real per-decision `reasoning` (shortest 270 characters, longest 2,954), one Parse Failure, one Ultimate, the Token Bank drained 25,000 → 11,615, ending `p2` on health at the 1,200-tick timeout. It replays to its own Final-State Hash with no divergences and validates against `command-log.v2.schema.json` unchanged. It is the flagship replay the player opens on (`startup.ts`'s `DEMO_REPLAY_URL`, and `index.html`'s preload with it).

**Model choice was measured, not preferred**, and this is the finding that decided the story. `reasoning` in a Command Log is `message.reasoning` from the provider — a field `openai-wire.ts` maps and does not invent. Probed against the live endpoint on 2026-08-11 with the exact body the adapter sends: `openai/gpt-oss-120b` returned 565 characters of reasoning and 128 `reasoning_tokens`; `openai/gpt-oss-20b` returned 1,115 and 261; **`llama-3.3-70b-versatile` and `qwen/qwen3.6-27b` returned no `reasoning` field at all** (qwen puts its deliberation in `<think>` tags inside `content`, which is the raw response, not reasoning). A Match between the two llama rows — the obvious default, and the one `configs/tournament.config.json` names — would have produced a log whose every `reasoning` was `null`, which is the exact defect this story exists to fix, while passing every other check.

## Two defects in shipped code that only a real provider call could find

**`debitTokenBank` crashed on Decision Point one.** Groq answered with `completion_tokens: 186` and `prompt_tokens_details.cached_tokens: 256`. The bank meters **completion** tokens; an OpenAI-compatible provider reports its cache signal against the **prompt**; the guard `cachedTokens > tokensSpent` encodes the assumption that one is a subset of the other, and it is false. The Scaffold is byte-identical on every call by construction (INV-7), so a warm prompt cache is not an edge case — it is every call after the first, and **any live tournament segment would have died the same way**. The change made is the narrowest safe one: an incommensurable count takes Story 3.5's own AC5 conservative path (full `tokensSpent` charged) instead of throwing, and `billable` can no longer go negative, so the bank cannot grow. It is safe rather than correct — 14 of the 57 shipped decisions were still discounted by 256 — and the semantics question (should a prompt-cache count reduce a completion-token debit at all?) is a Story 3.5 decision whose narrowest fix is one line in a provider adapter, which this story's Scope forbids touching. Escalated as deferred work with the measurements, not settled here. `packages/core/src/token-bank.ts` is not in this story's Scope list and the change is recorded as a deliberate, minimal exception to it.

**An empty completion drew as a blank box.** At tick 960 `openai/gpt-oss-20b` spent 2,046 of its 2,048 completion tokens deliberating and returned `content: ""`. The panel said "no valid Action could be read from this response" above an empty framed `<pre>`, which reads as a rendering bug rather than as the most interesting Parse Failure in the corpus. It now states the fact — the call returned no content at all — and omits the empty block.

## Independent review (opus, on the diff)

Twelve findings; every one was acted on or answered. **Fixed:** the reasoning attribution sat below the fold (moved above the body); `reasoning-panel-shows-text` reported the hovered card's agent index and never asserted it, so a regression selecting the wrong fighter's card would have passed (now asserted — and both fighters here share a provider and endpoint, so the attribution check could not have told them apart); `token-bank-hud-draws` required only bar-frame ink, which `drawArcadeBar` paints at *any* fill including an exhausted bank, so a bank that never moved would have passed (now reads a ladder of four scrub positions and requires two distinct levels per side — it reports 4/4); the same check's cinematic branch failed with a message that read like a benign skip, and the review's prediction that it would bite came true on the very next run when 85% landed inside the Ultimate freeze, which is why it is a ladder rather than two fixed points; Story 4.2's 32 KB first-frame payload budget was left guarding `demo.command-log.json` after the flagship moved, so nothing bounded the document that now blocks (the exhibition log is asserted at 17.6 KB against the same budget; the 125 KB sidecar is deliberately unbudgeted, being sheddable by design — a budget on it would be a budget on how much a model may think); a live API key was stashed in a scratchpad file outside the repository to keep it off every command line, which `assert-no-secret-leak.sh` is structurally blind to (deleted, and rotation is recorded as still owed); `docs/ASSETS.md` had no row for either artefact, which matters more here than for its siblings because this is the **first committed artefact in the repository whose content is not ours** — 125 KB of verbatim model output, now documented as such, along with the fact that regeneration is deliberately not byte-reproducible; and a source comment in `token-bank.ts` claimed a deferred-work entry that did not yet exist (written). **Answered rather than changed:** AC5's incidental exclusion is now pinned by a test carrying the ratchet in its failure message, with the durable fix filed as deferred work — the alternative was falsifying the log; `configs/exhibition.config.json`'s `seedCount: 1` is required by `parseRunConfig` rather than read by the generator and its comment now says so; `apps/web/dist/` holds a stale preload URL and is gitignored build output. The review independently confirmed the categories it found nothing in: no frozen contract touched, no determinism break (`debitTokenBank` has exactly one non-test caller and neither replayer reaches it, so no committed log's hash moved and the 100-in-process/100-spawned-process gates are unaffected), nothing fabricated in the shipped artefact, the fixture unreachable from the bundle, INV-8 intact, and both new checks genuinely load-bearing — a revert to the bot log fails `reasoning-panel-shows-text` on all three of its independent guards and `token-bank-hud-draws` because `drawTokenBank` is never called for a bot.

## Standing rule

If it appears to require a paid endpoint, a stored key, or a stubbed model response presented as a real one, **stop** — a fabricated LLM replay on a benchmark's front page is worse than no replay at all, and the operator path exists so that it never has to be considered.
