# Story 3.3 — Cerebras and Google AI Studio adapters

As the developer, I want each ranked Deployment on a different provider, so that free-tier quotas are independent budgets rather than one shared ceiling.

**Requires human-supplied `CEREBRAS_API_KEY` and `GOOGLE_AI_STUDIO_API_KEY`. Escalate if absent.**

## Acceptance criteria

**Given** the two new adapters, **When** either plays a Match, **Then** a valid Command Log is produced with the correct `provider` and real endpoint per call.

**Given** a config placing two *ranked* Deployments on one provider, **When** validated, **Then** a warning is raised — quotas would no longer be independent.

**Given** adding a provider, **When** the change is reviewed, **Then** neither `packages/core` nor any Environment Adapter was modified.

**Given** an OpenRouter Deployment, **When** it is configured for a tournament, **Then** configuration rejects it. OpenRouter free is 50 RPD and is reserved for the Metering Probe and BYOK.

## Scope

`packages/providers`: Cerebras and Google AI Studio adapters, plus the free-tier config file. Measured 2026-07-30 — Cerebras 30 RPM / ~1,000 RPD; Google AI Studio Gemini 2.5 Flash 10 RPM / 1,500 RPD, Gemini 2.5 Pro only 50 RPD. **Re-verify.**

## Frozen contracts touched

None modified.

## Invariants at risk

- **INV-4**, **INV-6**, **INV-8** — as story 3.2.

## Architecture decisions that constrain this

- **AD-9** — stateless adapters; quota state in the runner.
- **AD-1** — adding a provider must not touch core.

## Test plan

Fixture-based parsing per provider. One opt-in live smoke test each. Config validation rejecting two ranked Deployments on one provider, and rejecting OpenRouter for tournament use.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.
