# Story 8.1 — Command Log schema v2

As the engine, I want a versioned superset of the v1 Command Log schema, so that vertical position, Zone, and Juggle Count have somewhere to live before any story that produces them is written.

## Acceptance criteria

**Given** the v1 schema, **When** v2 fields are added (vertical position, Zone, Juggle Count on the per-Decision-Point entry; a third `agentIdentity.kind` value `"human"`), **Then** no v1 field is removed or repurposed — v2 is a strict superset.

**Given** a v2 Command Log, **When** a v1-only reader loads it, **Then** it hard-fails on `schemaVersion` mismatch rather than partially reading it — the same behaviour AD-3 already requires, exercised against a second version for the first time.

**Given** a v1 Command Log, **When** a v2-only reader loads it, **Then** it also hard-fails. No reader implements both versions at once.

**Given** the `action` enum, **When** `jump` is added, **Then** the existing six-minus-one v1 values (`advance`, `retreat`, `attack`, `block`, `special`, `stand`) are unchanged in spelling and meaning.

**Given** a Command Log entry with `agentIdentity.kind === "human"`, **When** rating computation runs, **Then** that Match is excluded from all rating output — the same mechanism AD-11 already uses to keep `provider: "byok"` off the leaderboard.

## Scope

`docs/contracts/command-log.schema.json` and `docs/contracts/index.ts` only. No `packages/core` or `packages/env-fighter` change — this story versions the contract; stories 8.2-8.4 populate it.

## Frozen contracts touched

Both frozen files, deliberately — this is the one story in Epic 8/9 whose entire job is to change them. Pre-authorized by PRD FR-33 and architecture AD-13; not an escalation trigger for this story specifically.

## Invariants at risk

- **INV-2** — replaying a v1 log must still reproduce its original Final-State Hash after this change lands; a v2-aware hash function must not accidentally alter v1 hashing.
- **INV-6** — the provider/endpoint-per-call guarantee must hold unchanged for the new `agentIdentity.kind` value.

## Architecture decisions that constrain this

- **AD-3** — schema version is exact-match, unknown versions hard-fail. This story adds the second version this rule has ever had to handle.
- **AD-13** — this story *is* AD-13's implementation: additive-only fields, engine and player version together.
- **AD-14** — the schema-level half of "a human is Agent-shaped": the `kind` enum value and the rating-exclusion behaviour.

## Test plan

Schema validates a hand-built v2 fixture log. Schema rejects a v1 log mislabelled as v2 and a v2 log mislabelled as v1. A v1 fixture's Final-State Hash is byte-identical before and after this change. A fixture with one `kind: "human"` decision entry is asserted absent from rating output.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero.

## Standing rule

This story is the pre-authorized exception for `docs/contracts/`. No other Epic 8 or Epic 9 story may touch the schema — if one appears to need a field this story didn't add, stop and escalate back to this story's scope rather than widening the schema inline from inside a gameplay or presentation story.
