# Story 7.3 — Behavioural metrics alongside skill

As a reader, I want to see how a model spent its thinking, not only whether it won, so that the benchmark says something a win rate cannot.

## Acceptance criteria

**Given** published results, **When** they render, **Then** each Deployment shows tokens per Match, reasoning-token share, parse-failure rate, and bank-exhaustion rate.

**Given** a Deployment beaten by a Baseline Bot, **When** results render, **Then** it is displayed plainly — not hidden, not filtered, not footnoted away. **If frontier models lose to the scripted bot, that is the headline.**

**Given** a Deployment whose reasoning tokens were never reported, **When** reasoning-token share renders, **Then** it shows as not-reported rather than as zero.

**Given** parse-failure rate, **When** it is presented, **Then** it is framed as a measurement, never as a defect to be driven down.

## Scope

Metrics computation and presentation from committed Command Logs.

## Frozen contracts touched

None modified — every input already exists in the schema.

## Invariants at risk

- **INV-5** — not-reported must never be rendered as zero.
- Parse failures are a first-class metric; do not let presentation imply otherwise.

## Test plan

Metric computation against fixture logs with known values. Not-reported versus zero distinction. A test that a bot-beats-Deployment row survives rendering unmodified.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.
