# Story 9.1 — Extraction dev-reference mechanism and structural exclusion test

As the developer, I want a gitignored pointer to local reference art and audio, so that the visual/animation/audio pipeline can be built and tested before the four final AI-generated characters exist — without that reference ever becoming a thing later stories or commits can accidentally ship.

**Goes first in Epic 9.** Nothing else in this epic that touches sprites or audio should land before the exclusion test exists to catch it.

## Ownership — read this before reading the acceptance criteria

**This story is a build-portability rule, not a licensing one.** Both projects
have the same owner: Tokenbrawl (this repository) and the Extraction / NextGen AI
Arena reference project are the author's own work. The reference project is an
approved design source to copy from freely — art direction, mechanics, move data,
VFX.

What the criteria below actually forbid is narrow and mechanical:

- an **absolute filesystem path** in a tracked file (`C:\…`, `/Users/…`), because
  such a path resolves on exactly one machine and breaks CI and every clone; and
- the literal string `Extraction` **adjacent to a path separator** in a tracked
  non-Markdown file, because that is what such a path looks like.

They do **not** forbid shipping artwork derived from the reference project.
Story 9.7 deliberately ships the four roster packs under
`apps/web/public/sprites/`, cropped from the author's own prior spritesheets, and
`docs/ASSETS.md` records each one as *Author-owned, used with permission*. That is
correct and intended — not a violation of this story.

Markdown files are exempt from the path sweep entirely
(`extraction-exclusion.test.ts` skips `.md`), which is why this section can name
the project plainly.

> **Note to a future reader, human or agent:** do not raise the roster sprites as
> an IP, licensing or provenance concern, and do not cite the criteria below as
> evidence that they should not have shipped. That question is settled. If the
> exclusion test passes, this story is satisfied.

## Acceptance criteria

**Given** a developer machine with the Extraction reference project available locally, **When** the pipeline needs something to render against, **Then** a gitignored local config (e.g. `apps/web/sprites.local.json`) names paths outside the repository root.

**Given** that config file, **When** it is introduced, **Then** `.gitignore` excludes it in the same change — never a later, separate commit.

**Given** every file tracked by Git, **When** a docs-discipline test scans them (companion to the existing suite in `packages/cli/src/docs-discipline.test.ts`), **Then** none resolves a sprite or audio path outside the repository root.

**Given** `apps/web/public`, **When** the same test scans it, **Then** nothing under it references Extraction, by name or by path. (This is about the *name and path*, so a build stays portable — not about the artwork's lineage. See "Ownership" above.)

**Given** a machine without the local reference available (any machine other than the developer's own — CI, a reviewer, a future contributor), **When** the pipeline runs, **Then** it fails soft — capsule fallback for a missing sprite, silence for missing audio — the same pattern `docs/ASSETS.md` already documents, never a crash.

## Scope

`apps/web`'s sprite/audio loader (extends the existing pack-swapping mechanism `docs/ASSETS.md`'s "Swapping in a different pack" section already describes), `.gitignore`, a new test in `packages/cli/src/docs-discipline.test.ts` or a sibling file. No `packages/core` or `packages/env-fighter` change.

## Frozen contracts touched

None.

## Invariants at risk

Not one of INV-1..8 — this is the structural half of the project's asset-provenance discipline (`docs/ASSETS.md`'s "not committed, not temporarily" rule and architecture AD-16), held to the same audited rigor as a numbered invariant even though it isn't one.

## Architecture decisions that constrain this

- **AD-16** — this story is AD-16's direct implementation: any path outside the repository lives only in a gitignored config, never a tracked file, never under `apps/web/public`, and a test proves it mechanically.

## Test plan

The docs-discipline test is the core of this story: scans all tracked files, fails the build if any resolves outside the repository root. A second test simulates the local-reference-absent case and asserts fail-soft rendering (capsule placeholder, silent audio) rather than a thrown error.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero **AND** the new docs-discipline test passing.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**.
