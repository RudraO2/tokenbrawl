# Story 12.10 — Six stages, and a backdrop with depth in it

As a viewer, I want the fight to happen somewhere, so that every Match is not the same dimmed painting behind the same two fighters.

## The gap, measured

`apps/web/public/sprites/mountain-dusk/` is the whole of this project's scenery: **one** stage, drawn by `apps/web/src/render/backdrop.ts` as a static layer stack, dimmed toward the ground colour so it does not fight the fighters for contrast.

`<REF>/game_assets/stages/` holds **six** stages (`s1.png`–`s6.png`) plus three NPC layers.

And the backdrop is flat by construction. `backdrop.ts` line 9:

> *"Static, not parallaxed: the arena is a single fixed horizontal axis with **no camera**, so there is nothing for parallax to be relative to, and inventing a scroll would be motion that does not correspond to anything in the simulation."*

That reasoning was exactly right when it was written and Story 12.3 removed its premise. There is a camera now. A parallax offset derived from the camera's own `x` corresponds to something in the simulation — the fighters' positions — so it is not invented motion, which is the specific thing the docblock refused. This story is the second half of a sentence 12.3 started, which is why it depends on it.

The reference frame is the argument: `<REF>/shots/04_local_match.png` has sky and clouds at the back, a distant treeline, a banner wall with lanterns and a crowd in the middle, and a wooden floor at the front. Four depths. Ours has one dimmed painting.

## What this story does

1. **Ships the stages.** Copied bytes from `<REF>/game_assets/stages/`, same owner, provenanced in `docs/ASSETS.md` as the sprite packs already are. The reference's absolute path and its project name must never appear under `apps/web/public/` — in a filename or in file contents (`packages/cli/src/extraction-exclusion.test.ts`, AD-16). A stage directory is named for what it is, not for where it came from.
2. **Gives each stage layers with depth factors.** `BackdropLayout` already carries `scale`, `dim` and an ordered `layers` array; it gains a per-layer depth so a layer can be told how much of the camera's movement to take. `validateBackdropLayout` validates it the way it validates everything else — a layout document is fetched JSON and therefore untrusted.
3. **Keeps the dim.** The reason it exists has not changed: a full-strength painting drops the bone-white sprites' contrast below the point where the action reads, and scenery that competes with its subject is a defect. Six stages means six chances to get this wrong, so the dim is per-stage and each value is recorded.
4. **Picks a stage.** Selectable on the character-select screen beside the fighters (which is why this story depends on 12.5), with a deterministic default so a first load, a direct replay link and the hero raster all draw the same stage.

**The parallax is a pure function of the camera.** `offset = cameraX * depth`, computed fresh each frame from the camera value 12.3 already returns. No accumulator, no scroll state, no `deltaTime` — the reference's own scroller is a stepped mutable, which is one of the four mechanisms that may never come across. A scrub to frame 90 must draw the backdrop at exactly the offset a play-through to frame 90 draws.

**`docs/DESIGN.md` bans parallax — for the page.** Its Motion rule ("no easing curve, no spring, **no parallax**, no scroll-jacking") governs page chrome, and the 2026-08-07 ruling scoped the flat-surface rules to the UI. A backdrop layer moving with the camera inside the arena is not scroll-jacking; it is the arena drawing depth. Recording this here matters because the word "parallax" appears in the banned list and a reader who stops there will read this story as a violation.

## Acceptance criteria

**Given** the arena drawing any stage, **When** the camera pans (the arcade fighter walking from centre to wall), **Then** the far layers shift by strictly fewer pixels than the near layers — the check `stage-parallax-has-depth`, added to `scripts/visual-gate.mjs` by this story, which hashes an upper and a lower horizontal strip of the arena canvas before and after a pan and requires the near strip to change while the far strip changes less.

**Given** each shipped stage, **When** it is selected and a Match drawn, **Then** the arena canvas hashes differently from every other stage's and each clears the 2% ink floor — the check `every-stage-draws`, which iterates the stage list rather than a hardcoded count, so a stage added later and left unwired fails rather than ships.

**Given** any stage, **When** it is drawn, **Then** the fighters still read against it: this story records, per stage, the measured contrast of the bone-white sprite against the stage's dimmed mid-tone, and the dim value chosen to reach it. The 3:1 graphical-object floor from `docs/DESIGN.md`'s "Two regimes" is the check applied, as it was for the arena palette.

**Given** the replay player scrubbed to an arbitrary frame, **When** the same frame is reached by playing forward, **Then** the backdrop's layer offsets are identical. Parallax is pure or it is a clock.

**Given** a visitor with `prefers-reduced-motion: reduce`, **When** the camera moves, **Then** the layers still track it. Parallax here is a consequence of where the fighters are, not an animation played at the viewer — but if the story concludes otherwise, it must say so and pin the layers instead, rather than leaving the question unanswered.

**Given** the hero raster, **When** `apps/web/scripts/build-hero.mts` runs, **Then** it builds and draws its stage.

**Given** the page's load, **When** measured, **Then** the stages are late upgrades to an already-running fight exactly as the sprite packs are (`startup.ts`), and the added payload is recorded and under the budget this story states. Six stages is six times the scenery bytes, on a static site with no CDN.

**Given** every added file, **When** `extraction-exclusion.test.ts` and `scripts/audit-invariants.sh` run, **Then** they pass, and every file has a `docs/ASSETS.md` row with source, licence and date.

**Given** any committed Command Log, **When** replayed, **Then** its Final-State Hash is unchanged.

## Scope

`apps/web/public/sprites/` (or a new `apps/web/public/stages/` — the story picks one and says why), `apps/web/src/render/backdrop.ts` (depth per layer, and its docblock's "no camera, no parallax" paragraph, which becomes false and must be rewritten rather than left as a lie in the file that defines the behaviour), `apps/web/src/render/renderer.ts` (feeding the camera offset in), the character-select screen (the stage picker), `apps/web/src/startup.ts`, `apps/web/scripts/build-hero.mts` if the hero's stage is chosen there, `scripts/visual-gate.mjs` (two checks), `docs/ASSETS.md`.

## Frozen contracts touched

None. A stage is presentation and appears in no Command Log field. If a stage seems to need recording in a log so a replay draws the same scenery, **stop and escalate** — the answer is a deterministic default derived from something already in the log (the seed), not a new field.

## Invariants at risk

- **INV-1 / INV-3** — the parallax offset comes from the camera, which comes from the frame. No clock anywhere in the chain.
- **INV-8** — self-hosted assets only.
- **AD-16** — the reference's name and path never reach `apps/web/public/`.
- **AD-15** — presentation only.

## Two regimes

`apps/web/src/render/**/*.ts` is the arena and is released from the translucency, gradient and `globalAlpha` rules — which is what lets a layer be dimmed by compositing rather than by a pre-baked darker image. Geometry and type stay global. `docs/DESIGN.md`'s no-parallax rule is a **page** motion rule; see the paragraph above, and read the "Two regimes" section before drawing.

## Test plan

- `validateBackdropLayout` rejects a malformed depth exactly as it rejects a malformed scale or dim.
- The layer offset is pure in the camera value.
- Every stage in the shipped list has a layout document, every layer named in a layout has a file, and every file is referenced by a layout. All three directions, because Story 9.7 shipped assets nothing referenced and Story 11.6 found a code path that referenced assets it never drew.
- A stage selection round-trips to what is drawn.
- The hero builds.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero **AND** `node scripts/visual-gate.mjs` exiting zero with `stage-parallax-has-depth` and `every-stage-draws` passing. The Visual check finding records the per-stage dim values, the measured sprite-against-stage contrast, and the added payload.
