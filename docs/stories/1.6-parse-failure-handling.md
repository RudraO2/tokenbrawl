# Story 1.6 — Parse failures as a first-class metric

As the developer, I want parse failures recorded rather than retried, so that extra compute is never handed to whichever model is worst at following the format.

## Acceptance criteria

**Given** a response containing no valid Action, **When** it is processed, **Then** exactly one Agent call was made. No retry.

**Given** a Parse Failure, **When** the Fallback Action is applied, **Then** it is `stand` — never `block`, never `special`, never a repeat of the previous Action.

**Given** a Parse Failure, **When** the log entry is written, **Then** `parseFailure` is true and `rawResponse` holds the verbatim response.

**Given** a completed Match, **When** metrics are computed, **Then** parse-failure rate is reported per Agent.

## Scope

Response parsing and fallback in `packages/core`. The Action grammar is core-owned and identical for all Deployments.

## Frozen contracts touched

None modified. The schema already enforces `action: "stand"` when `parseFailure` is true.

## Invariants at risk

- **INV-1** — a retry hands extra compute to a weaker parser, reintroducing the confound.
- **INV-7** — do not loosen the grammar for a specific Deployment. A model that needs different phrasing is a published caveat.

## Architecture decisions that constrain this

- **AD-7** — Action grammar lives in core.

## Test plan

Exactly-one-call assertion. Fallback is `stand` under every malformed-input shape tried. Never `block`, `special`, or repeat-last. Rate appears in metrics output.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**. Never widen a frozen interface.
