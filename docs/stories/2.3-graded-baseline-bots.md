# Story 2.3 — Three graded baseline bots

As the developer, I want scripted opponents of deliberately different strength, so that the game can be measured before a single token is spent.

## Acceptance criteria

**Given** the random bot, **When** it acts, **Then** it selects uniformly from legal Actions using the match PRNG — never `Math.random`.

**Given** the aggressive bot, **When** it acts, **Then** it closes distance and attacks whenever off cooldown, with no punish awareness.

**Given** the spacing-aware bot, **When** it acts, **Then** it holds effective range, attacks only when the opponent is inside it, and punishes observed recovery.

**Given** any Baseline Bot, **When** it plays, **Then** it consumes zero tokens and its log entries carry `kind: "bot"` with no `deployment` object.

**Given** the same seed and opponent, **When** a bot plays twice, **Then** it produces an identical action sequence.

## Scope

`packages/env-fighter`: three bots implementing the `Agent` port. These are permanent fixtures, not scaffolding — FR-23 requires them in every published results table, and they are the skill floor the leaderboard is read against.

## Frozen contracts touched

`docs/contracts/index.ts` `Agent` — implemented. Note `AgentIdentity` forbids `deployment` when `kind` is `bot`.

## Invariants at risk

- **INV-2** — a bot reading `Math.random` breaks replay determinism. Use the threaded PRNG.

## Architecture decisions that constrain this

- **AD-1** — bots depend on core, never the reverse.

## Test plan

Determinism per bot under a fixed seed. Zero token consumption. Schema conformance of bot log entries. Behavioural sanity: the spacing bot does not attack out of range; the aggressive bot does attack out of range.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**. Never widen a frozen interface.
