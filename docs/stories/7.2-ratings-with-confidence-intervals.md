# Story 7.2 — Ratings with bootstrapped confidence intervals

As a sceptical reader, I want confidence intervals on every rating, so that I can tell a real difference from twenty matches of noise.

## Acceptance criteria

**Given** any published rating, **When** it appears, **Then** it carries a bootstrapped confidence interval. **No raw win table is ever published without CIs.**

**Given** any results table, **When** it is generated, **Then** the Baseline Bots appear as rows in it.

**Given** Reflex-Track Deployments, **When** results are rendered, **Then** they appear in a separate, labelled table and are never merged into the main leaderboard.

**Given** BYOK Matches, **When** ratings are computed, **Then** they are excluded entirely.

**Given** the bootstrap, **When** it runs, **Then** its resampling is seeded so the published numbers reproduce.

## Scope

Rating computation and leaderboard generation. Elo or TrueSkill — the architecture deliberately leaves the choice open, because either satisfies AD-11 and AD-12 and the choice causes no divergence between components.

## Frozen contracts touched

None modified.

## Invariants at risk

- **INV-5** — Reflex Track must never merge into the main board.
- **INV-6** — two endpoints of one model are two rows.

## Architecture decisions that constrain this

- **AD-11** — BYOK excluded; Reflex Track separate; provenance per call.

## Test plan

Bootstrap implementation against a known distribution. Seeded reproducibility of published numbers. A test that a table cannot render without CIs. Bot rows present. Reflex Track separation. BYOK exclusion.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**.
