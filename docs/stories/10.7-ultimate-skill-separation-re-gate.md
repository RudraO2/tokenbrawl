# Story 10.7 — Ultimate economy skill-separation re-gate

**Closes Epic 10. Nothing in this epic ships until this passes.**

As the developer, I want the graded Baseline Bot ladder re-run against the new Ultimate economy, so that a balance change cannot quietly destroy the skill separation the whole benchmark rests on.

## Why this is mandatory, not diligence

Story 2.4's own record is the argument, and it is worth restating because it is the exact failure this story exists to catch.

At `blockDamageReduction: 5`, a guard denied 5 damage but cost the guarding fighter its own attack — worth about 7 — so blocking was strictly dominated by trading. An exhaustive search over all 64 in-range policies found **zero** that beat the aggressive bot, under any Commitment Window shape tried. Defensive skill did not merely underperform; it did not exist.

And the config still ran. It still hashed deterministically. It would still have produced a leaderboard, with confidence intervals, that looked entirely credible.

Story 10.2 moves `specialMeterCost` from 50 to 100. That halves how often the Ultimate is available across a Match and changes which Actions are legal at which moments for every Baseline Bot and every Deployment. It is precisely that class of change.

## Acceptance criteria

**Given** the graded Baseline Bot ladder from Stories 2.3 / 2.4 / 8.5, **When** it is re-run against the new Ultimate economy, **Then** it clears the FR-3-equivalent thresholds over the same Match count per pairing as the original gate.

**Given** a failure, **When** it is handled, **Then** Epic 10 re-opens and Story 10.2's numbers are revisited. **The thresholds are never lowered.** Lowering a threshold to pass a gate converts the gate into decoration.

**Given** a pass, **When** it is recorded, **Then** the report lands under `docs/reports/` alongside the existing gate reports, and states the economy it was run against (`specialMeterCost`, `specialDamage`, and the invulnerability window) so a future reader can tell which configuration it certifies.

**Given** the re-gate, **When** it is run, **Then** it uses the existing ladder harness (`packages/env-fighter/src/testing/skill-ladder.ts` and its siblings) rather than a new one written for this story.

## Scope

`packages/env-fighter/src/skill-gate.test.ts` and the testing harness under `packages/env-fighter/src/testing/`, plus a new report under `docs/reports/`. No production behaviour change — if this story appears to need one, the correct response is to re-open Story 10.2, not to edit the engine here.

## Frozen contracts touched

None.

## Invariants at risk

None added. This story is the guard on the invariant Epic 2 established: that this game separates skill from luck.

## Test plan

The gate *is* the test. It runs the ladder over the required Match count per pairing and asserts the thresholds.

## Exit gate

The gate report committed under `docs/reports/`, showing a pass, and naming the economy it certifies.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**. If it fails, **escalate rather than adjusting the thresholds.**
