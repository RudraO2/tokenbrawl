# Story 5.1 — Local CLI

As a developer or power user, I want to run matches and tournaments from the command line, so that heavy runs do not depend on a browser tab staying open.

## Acceptance criteria

**Given** the CLI, **When** it runs a Match, **Then** it uses the same Harness and the same Command Log schema as CI — no forked logic anywhere.

**Given** CLI output, **When** it is loaded by the player, **Then** it plays without conversion.

**Given** a provider key in the environment, **When** the CLI runs, **Then** the key is read from the environment only and never written to disk or into a log.

**Given** a tournament invocation, **When** it is interrupted and rerun, **Then** it completes only the outstanding Matches.

## Scope

`packages/cli`: match and tournament entry points, config loading, output to `replays/`. Thin wrapper over core — if logic starts accumulating here that CI also needs, it belongs in core.

## Frozen contracts touched

None modified.

## Invariants at risk

- **INV-2** — CLI-produced logs must replay identically to CI-produced ones.
- **INV-8** — no daemon, no background service.

## Architecture decisions that constrain this

- **AD-2** — same Command Log format as everything else.
- **AD-9** — resumable state is the set of committed logs, not a separate store.

## Test plan

Byte-identity between a CLI-produced log and a programmatically-produced one for the same seed. Player loads CLI output unmodified. Resume-after-interrupt. Key never written to disk.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.
