# Story 4.4 — Token Bank HUD

As a visitor with no context, I want to see a second meter draining beside each health bar, so that I work out on my own that the fighter is running out of thinking.

## Acceptance criteria

**Given** playback at any position, **When** the HUD renders, **Then** the meter reflects `bankRemaining` from the Command Log at that Decision Point.

**Given** a Token Bank reaching zero, **When** it does, **Then** the meter enters a **visually distinct** state — a viewer who has read nothing should notice the moment it happens.

**Given** a Baseline Bot, **When** it plays, **Then** no Token Bank meter is shown for it, because it consumes no tokens.

**Given** both banks emptying, **When** playback continues, **Then** both meters show the exhausted state and the fight continues.

## Scope

`apps/web`: the HUD, positioned beside the health bar. This is what makes UJ-2 work — the shareable moment is a viewer noticing a fighter suddenly making instant stupid decisions and connecting it to the empty meter.

## Frozen contracts touched

None modified.

## Invariants at risk

- **INV-3** — the meter shows tokens, never seconds.

## Test plan

Meter value correspondence at sampled Decision Points. Distinct zero state. Bot case shows no meter. Both-exhausted case. Visual verification via the Chrome DevTools MCP — this one is judged by eye as much as by test.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.
