# Story 12.1 — The visual gate becomes a command

As the developer, I want the visual check to be an executable gate in the verify block rather than a runbook step, so that a defect a screenshot would reveal cannot reach `done`.

**Goes first in Epic 12.** No other story in this epic lands before this one. Every story after it screenshots the product it is changing, and a story that starts from an unverified frame accepts whatever is already wrong in that frame.

## Why this story exists

Story 10.1 built the right idea and stopped one step short. It wrote `docs/VISUAL-CHECK.md`, added the visual check to `docs/stories/README.md`'s universal rules, and stated the rule that all three surfaces are captured every time. Then twelve more stories shipped across Epics 10 and 11, all green, and a hand audit on 2026-08-10 found:

- **Play vs CPU has no canvas at all.** `arcade/run.ts` says so in its own docblock — the Match runs headlessly and the player is re-mounted only once it has finished. A visitor presses keys blind for a full Match. Verified live: the page holds exactly two canvases, one under `#app` and one under `#spectate`, and none under `#arcade`.
- **The page scrolls sideways on a phone.** At 390×844, `scrollWidth` is 992 against a `clientWidth` of 390. The 960px arena canvas does not scale.
- **Two of four characters are unreachable.** `render/roster.ts` freezes `DEFAULT_ROSTER` to `['clawde','chatty']`; gemini and grokk ship full sprite packs and portraits that nothing can select.
- **The Ultimate cinematic fires once in the entire shipped corpus.** `special` costs the whole bar, and across all seven committed Command Logs the action appears exactly once, in `spectate-03` at tick 870 — with sound off by default.

Story 10.1's acceptance criteria are the reason. Read them again: *"the gate **includes** starting the dev server, loading the page, and capturing a screenshot"*, and *"the comparison is recorded in the story file as a short written finding"*. Both describe what a person should do. Neither can fail a build. `.bmad-loop/policy.toml`'s `[verify]` block — the thing that actually decides whether a story commits — held two commands, one that asserts canvas call sequences and one that greps source, and a prose runbook is not a third.

The lesson is not that the advice was wrong. The advice was right and was followed inconsistently for forty stories, which is what advice does. This story converts the checkable half into code.

## Acceptance criteria

**Given** a checkout with Chrome installed, **When** `npm run visual-gate` runs, **Then** it starts the dev server, drives headless Chrome, captures all three surfaces at 1440×900 and 390×844, writes them plus a `report.json` under `docs/visual/<label>/`, and exits non-zero if any unwaived check failed.

**Given** the gate, **When** it runs, **Then** it adds no dependency to the repository: Node 22's global `WebSocket` speaks the DevTools Protocol directly, and `CHROME_PATH` overrides the browser search.

**Given** `#arcade`, **When** the gate clicks its Play-vs-CPU control and waits, **Then** the check `arcade-live-canvas` passes only if a visible canvas exists under that host while the Match is being played.

**Given** the 390×844 viewport, **When** the gate measures the document, **Then** `no-horizontal-overflow` fails if `scrollWidth` exceeds `clientWidth`, and names the three widest offending elements so the failure is actionable without a second run.

**Given** any visible canvas, **When** the gate samples its pixels through `getImageData`, **Then** `canvas-not-blank` fails below 2% ink — the shape of an unwired asset or a dead frame.

**Given** the Spectate surface with playback started, **When** the gate hashes its pixels 700ms apart, **Then** `spectate-animates` fails if the hash is unchanged. This is the Story 11.6 defect ("whatever button I click, it's just one frame") expressed as a check.

**Given** the console, **When** the run ends, **Then** `console-clean` fails on any `error` or `warning` outside a short, commented allowlist — because `startup.ts`'s asset loaders warn instead of throwing, so a pack that failed to decode reports itself there and nowhere else on screen.

**Given** a check that fails today because a later story owns the fix, **When** it is named in `docs/visual/known-failures.json` with its owing story, **Then** the gate reports it and does not fail. **And given** a waived check that starts passing, **Then** the gate fails until its waiver is deleted. Without that second half a waiver outlives the defect it described.

**Given** `.bmad-loop/policy.toml`, **When** this story completes, **Then** `node scripts/visual-gate.mjs` is the third entry in `[verify] commands`.

## Scope

`scripts/visual-gate.mjs` (new), `docs/visual/known-failures.json` (new), `package.json` (one script), `.gitignore` (gate PNGs), `docs/VISUAL-CHECK.md`, `.bmad-loop/policy.toml`. No change to `apps/web/src` or any package — this story builds the instrument, it does not use it to fix anything.

## Visual check finding

Run label `story-12-1`, six captures, Chrome 1440×900 and 390×844.

- **Replay player (`#app`)** — draws correctly: sprites, backdrop, HUD, 98.0% ink. Fighters sit far right with roughly four fifths of the frame empty, which is the absent camera (`render/backdrop.ts`: *"the arena is a single fixed horizontal axis with no camera"*), owed by `12-3`.
- **Arcade (`#arcade`)** — the capture shows the section's status line reading "Fighting." with no canvas anywhere beneath it. This is the single most damaging defect in the audit and the screenshot states it plainly.
- **Spectate (`#spectate`)** — animates (hash changes across 700ms) and draws at 98% ink. `ULTIMATE READY` renders on top of the gold gauge and is unreadable; `HP 69` overlaps the bar below it. Owed by `12-6`.
- **Mobile** — the spectate canvas measures 992px against a 390px viewport, and `.tb-tagline` runs to 409px.

Against the reference (`shots/04_local_match.png`): the reference frames both fighters centre-screen at roughly a third of frame height with portrait, name, model line, round timer and win pips; this build has none of those five HUD elements and no camera to do the framing.

## Note for whoever runs the loop next

`apps/web/src/hero/hero.test.ts`'s determinism test took 5940ms against vitest's 5000ms default during this work and timed out once. The cause was an unrelated browser left rendering the fight at 60fps on the same machine, not this change — the suite passes 1125/1125 with it idle, and the gate leaks no Chrome of its own (`--user-data-dir` is `tb-visual-gate-<pid>`; none survive teardown). It is close enough to the limit to trip again on a loaded host, and it is worth a raised `testTimeout` the next time that file is touched.
