# Story 10.2 — The Ultimate costs the whole bar

As a visitor, I want the Super Gauge to be spent entirely by the Ultimate, so that seeing a full bar means something is about to happen.

## The measurement this story rests on

The obvious plan — "the reference super does 280 damage, ours does 16, so crank it" — is wrong, and measuring it is what keeps this story small.

| | NextGen AI Arena | Tokenbrawl today |
|---|---|---|
| Max health | 5000 | 100 |
| Basic attack | 50 (**1.0%** of health) | 7 (**7.0%**) |
| Heavy | 90 (**1.8%**) | — |
| Super / special | 280 (**5.6%**) | 16 (**16.0%**) |
| Super ÷ basic ratio | **3.1×** | **2.3×** |
| Meter cost | 100 of 100 — the whole bar | 50 of 100 — half |
| Invulnerability | 12 frames | none |

Tokenbrawl's `special` already removes a **larger** share of a health bar than the reference's super does — nearly three times the share. It does not read as an Ultimate because it costs half a bar, is invisible, and is over before a viewer notices it.

So this story barely moves damage. It changes what the Action **costs** and what it **protects**.

## Acceptance criteria

**Given** `DEFAULT_FIGHTER_CONFIG`, **When** the Ultimate's economy is set, **Then** `specialMeterCost` is `100` — equal to `maxMeter`, the whole bar — and `specialDamage` is `22`, derived as `attackDamage` (7) × the reference's own super-to-basic ratio (3.1), rounded.

**Given** a fighter below full meter, **When** `legalActionsFor` is asked, **Then** `special` is withheld — the existing mechanism at Story 2.2 AC3, with a new number. No new withholding path is introduced.

**Given** a fighter inside the Ultimate's startup or active phase, **When** an opposing strike would connect, **Then** it does not: the Ultimate carries invulnerability across `specialWindow.startup + specialWindow.active` (10 + 5 = 15 Ticks), mirroring the reference's 12-frame super invulnerability.

**Given** a fighter in the Ultimate's **recovery** phase, **When** an opposing strike connects, **Then** it deals full damage. Whiffing an Ultimate must remain the worst punish in the game — this is the property that keeps a full-bar Action from being strictly correct to throw out.

**Given** the invulnerability, **When** it is implemented, **Then** it is derived from the existing `committedAction` + `commitmentRemaining` pair via `phaseOf`, **never** stored as a new field on `FighterState`. The state object gains nothing to hash.

**Given** the Agent scaffold prompt, **When** it describes the Action set, **Then** `special` is described as a full-bar Ultimate, with its cost, damage and invulnerability window stated, so a Deployment can reason about *when* to spend it rather than merely learning that it is legal.

**Given** any Match replayed before and after this change, **When** their Final-State Hashes are compared, **Then** they differ — deliberately. This is a balance change, not a refactor, and the completion note must say so plainly.

## Scope

`packages/env-fighter/src/config.ts` (the two numbers), `packages/env-fighter/src/environment.ts` (invulnerability during the Ultimate's window), `packages/core/src/scaffold.ts` (prompt wording). No renderer change. No contract change.

## Frozen contracts touched

**None.** `special` is already a member of both `ACTIONS` and `ACTIONS_V2` in `docs/contracts/index.ts`. Raising its meter cost and damage changes no schema, so the standing escalation rule is not triggered. If this story appears to require a contract change, **stop and escalate** — it has been checked and it does not.

## Invariants at risk

- **INV-2 / AD-5** — every value stays a safe integer. `assertIntegerConfig` already enforces this and already rejects `specialMeterCost > maxMeter`; at exactly `maxMeter` the Action stays reachable, which that check permits.
- **INV-3** — the invulnerability window is counted in Ticks, never in time.

## Test plan

- An Ultimate in startup takes no damage from a connecting strike.
- An Ultimate in active takes no damage from a connecting strike.
- An Ultimate in recovery takes **full** damage — the punish property, asserted directly.
- `legalActionsFor` withholds `special` at 99 meter and offers it at 100.
- `assertIntegerConfig` still accepts the config with `specialMeterCost === maxMeter`.

## Completion note

Shipped 2026-08-06.

**What changed.** `specialMeterCost` 50 → 100, `specialDamage` 16 → 22, both with their derivation recorded in `config.ts` rather than left as bare numbers. `isInvulnerable` added to `frames.ts` — a pure function of the same `committedAction`/`commitmentRemaining` pair every other window question reads, so `FighterState` gained no field and nothing new is hashed. Applied in `environment.ts`'s hit-resolution loop, reading `preHitCommitted[opponentIndex]` rather than `committed[opponentIndex]` so that two fighters throwing an Ultimate on the same Tick are each judged against the other's pre-Tick state; with both invulnerable neither connects, which is the reference's beam-clash expressed as mutual immunity. `hitLanded` is deliberately left clear on a whiff into invulnerability, so the attacker's remaining active Ticks can still connect once it lapses.

The scaffold now describes `special` as an Ultimate — full bar, ~3x an attack, untouchable while it winds up and strikes, and "an Ultimate thrown at nothing is the worst position you can put yourself in." Placing it there is correct rather than a layering violation: `SCAFFOLD` already describes this duel specifically, and `observation.state` cannot carry prose because it is `canonicalStringify`'d integers.

**Regenerated artefacts.** The balance change invalidated six committed fixtures, exactly as this story's last AC anticipated: the demo replay, the hero Command Log, the ratings report, the side-advantage report, and both skill-gate reports. All regenerated through their own documented flags, never hand-edited.

**The re-gate passed — see 10.7.** Every threshold assertion in `skill-gate.test.ts` passed on the first run under the new economy; only the committed report *artefacts* were stale. Ordering held strictly with non-overlapping CIs: spacing-aware 1.0000, aggressive 0.4775, random 0.0225. Aggressive-over-random moved 0.9725 → 0.9550, comfortably above its 0.5000 floor.

**Defect found by the gate, and fixed.** The console showed `spectate-03/04/05` being skipped for failed hash verification — and the six precomputed spectate Command Logs had not occurred to me as fixtures needing regeneration, because no test covers them. Only the runbook's "check the console" step surfaced it. Regenerated via `build-spectate-manifest.mts`; all six now load. **A test-only exit gate would have shipped a Spectate stream missing half its entries.**

**Two findings logged, neither in this story's scope:**

1. *The hash-failure message is misleading.* `matchesRecordedHash` ANDs two comparisons — the replayer's verdict against the log's declared `finalStateHash`, and the film's independently recomputed hash against that verdict. The failure message in `spectate/walk.ts:75` prints only the second pair, which is why the console read `recomputed <X> vs recorded <X>` with two identical hashes while still failing. It should report whichever comparison actually failed.
2. *Fighters clip at the arena edge.* `interpolatedX` maps `arenaMin` to pixel 0 and the sprite is drawn centred on that x, so a fighter walked to the wall loses half its body off-canvas. The reference carries `WALLPAD = 90000` — "keep body centre off the walls" — and this project has no equivalent.
