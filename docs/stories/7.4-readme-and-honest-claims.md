# Story 7.4 — The README, the hero, and honest claims

As an engineer landing from a link, I want to understand this in thirty seconds and trust it under scrutiny, so that I can tell it apart from a weekend demo.

## Acceptance criteria

**Given** the README, **When** it opens, **Then** an autoplaying animation of a Match with reasoning visible appears above the fold, and it renders on GitHub without a click.

**Given** that animation, **When** it plays, **Then** it shows at least one Token Bank draining and at least one reasoning excerpt.

**Given** the README, **When** it is read, **Then** it contains **no novelty claim**. The stated claim is limited to: a latency-fair head-to-head harness where compute budget is an adversarial in-match resource, run with controls.

**Given** the README, **When** prior work is cited, **Then** it names `llm-colosseum`, *"Win Fast or Lose Slow"* (NeurIPS 2025), Orak, the token-budgeting literature (TALE, CostBench), and existing LLM game arenas (CATArena, CodeToPlay, LLM-PSRO).

**Given** the README, **When** the ranking basis is described, **Then** it states plainly that Tokenbrawl ranks **Deployments, not models**, and that free endpoints may serve quantised weights.

**Given** asset licensing, **When** it is documented, **Then** every sprite source and licence is recorded.

## Scope

`README.md`, the hero GIF generation, and the licence manifest. The hero is a **hard deliverable**, not a nice-to-have — recruiter signal and shareability were the stated success criteria.

## Frozen contracts touched

None.

## Invariants at risk

- **INV-6** — the ranking-Deployments disclosure is required, and the audit script checks the README for it.

## Test plan

A check that the README contains the disclosure string and every required citation. Manual verification that the hero autoplays on GitHub. Licence manifest completeness against the assets actually present.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.
