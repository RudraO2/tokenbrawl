# Story 8.3 — Zoned strikes and matched block

As the fight, I want `attack` and `special` to target a Zone and `block` to have to match it, so that blocking stops being a single always-correct button.

## Acceptance criteria

**Given** `attack` or `special` is committed, **When** it is submitted, **Then** it also carries a target Zone, `high` or `low`.

**Given** `block` is committed, **When** it is submitted, **Then** it also carries a Zone, and prevents damage only when that Zone matches the incoming strike's Zone.

**Given** a `block` on the wrong Zone, **When** a hit resolves, **Then** full damage applies — identical to submitting no block at all.

**Given** the Fallback Action (`stand`, Story 1.6 / FR-9), **When** it is applied on a Parse Failure, **Then** it carries no Zone — a Parse Failure cannot be accidentally rewarded by a lucky Zone guess, so FR-9's guarantee holds unchanged.

**Given** `legalActionsFor`-style gating, **When** Super Meter is below `special`'s cost, **Then** `special` is still withheld regardless of Zone — the Zone dimension does not create a new way around existing gating.

## Scope

`packages/env-fighter/src/frames.ts` (Zone as a parameter alongside the existing Commitment Window/range/damage lookups), `state.ts` (committed Zone stored per Agent as an integer code, alongside `committedAction`), `environment.ts` (Zone-match resolution in the hit-check). No `docs/contracts/` change.

## Frozen contracts touched

None. Story 8.1 already added Zone to the schema and grammar.

## Invariants at risk

- **INV-2** — Zone is an integer code in `FighterState` (hashable, per `canonicalStringify`'s integers-only rule) even though it is a string enum in the Command Log — the representations are deliberately different (AD-13), and this story is where that split becomes real code rather than a stated rule.
- **INV-7** — the Scaffold text describing Zone to an Agent must be byte-identical across every Deployment. No per-Deployment phrasing.

## Architecture decisions that constrain this

- **AD-5** — integers only in simulation state.
- **AD-7** — Core owns the Scaffold; Zone's description in the Action grammar prompt is identical for every Deployment.
- **AD-13** — this story is the concrete implementation of the schema-vs-state representation split AD-13 states.

## Test plan

Unit tests: matched-Zone block prevents damage, mismatched-Zone block takes full damage, Fallback Action never carries a Zone. Determinism fixture with Zone-varied sequences replays to an identical hash, in-process and cross-process. Scaffold byte-identity test extended to cover Zone-describing text.
