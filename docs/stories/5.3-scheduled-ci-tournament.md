# Story 5.3 — Scheduled CI tournament

As the developer, I want the tournament to run itself weekly and publish its own results, so that the site stays current without anyone being present.

**Requires provider API keys configured as GitHub Actions repository secrets. Escalate if absent — do not commit keys, and do not stub the workflow and mark it done.**

## Acceptance criteria

**Given** the cron schedule, **When** it fires weekly, **Then** the workflow runs the tournament on free CI minutes for a public repository.

**Given** a completed run segment, **When** it finishes, **Then** Command Logs and the updated leaderboard are committed back to the repository.

**Given** that commit, **When** it lands on the default branch, **Then** it triggers the static redeploy. No separate deploy hook is needed.

**Given** the five-day spread, **When** the tournament is scheduled, **Then** each run segment respects per-provider daily quotas and parks what it cannot complete.

**Given** a secret, **When** the workflow runs, **Then** it is read from Actions secrets and never appears in logs or in a committed file.

## Scope

`.github/workflows`: the cron tournament workflow. Roughly 4,500 calls per Deployment per tournament; the ~1,000-RPD providers are the binding constraint.

## Frozen contracts touched

None modified.

## Invariants at risk

- **INV-8** — free minutes on a public repository. No paid runner, no hosted service.
- **INV-6** — provenance survives the CI path into committed logs.

## Architecture decisions that constrain this

- **AD-9** — resumability across job boundaries is what makes the weekly schedule possible.

## Test plan

A manual `workflow_dispatch` run against a tiny roster proving the end-to-end path: run, commit, redeploy. Secret-leak check over workflow logs. A dry-run mode that exercises scheduling without spending quota.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero **AND** one successful end-to-end dispatch run.
