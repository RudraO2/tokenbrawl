# Story 8.4 — Multi-hit strings and juggle state

As the fight, I want chained hits to have a natural end, so that a combo is a skill expression and not a stunlock.

## Acceptance criteria

**Given** a hit lands while the defender is already in hitstun from a prior hit in the same chain, **When** the next hit lands before recovery, **Then** Juggle Count increments.

**Given** Juggle Count, **When** it passes a configured threshold, **Then** damage and/or hitstun scale down — a data table read by `frames.ts`-style lookup, never a magic number inline.

**Given** the defender, **When** it lands, blocks successfully, or returns to neutral, **Then** Juggle Count resets to zero.

**Given** a juggle chain, **When** Juggle Count reaches a configured maximum, **Then** the chain forcibly ends and the defender becomes actionable — regardless of further attacker input. This is `OQ-7`'s liveness property and it ships with a machine check, not just a design intent.

**Given** a defender inside a juggle chain, **When** a configured maximum Tick count elapses, **Then** the defender regains a real Decision Point even if the attacker keeps connecting — an explicit test asserts this over many seeded sequences, not just the single-hit-cap case above.

## Scope

`packages/env-fighter/src/state.ts` (Juggle Count per Agent), `frames.ts` (juggle scaling table), `environment.ts` (increment/reset/liveness-cap logic in hit resolution). No `docs/contracts/` change — Juggle Count already exists in the v2 schema per Story 8.1.

## Frozen contracts touched

None.

## Invariants at risk

- **INV-2** — Juggle Count is an integer, scaling is deterministic table lookup, no float.
- **New liveness property (not one of INV-1..8, audited with equal rigor per OQ-7):** no chain may hold a defender past the configured Tick cap. This needs its own machine check in the test suite — a design intent alone does not satisfy this story.

## Architecture decisions that constrain this

- **AD-5** — determinism is structural.
- **AD-13** — Juggle Count is the third of the three v2 fields Story 8.1 added to the schema; this is the story that makes it real.

## Test plan

Unit tests: Juggle Count increments per chained hit, resets on land/block/neutral, damage/hitstun scale past threshold per the data table. Liveness test: a fuzzed/seeded run where the attacker always attacks optimally never holds the defender past the configured Tick cap — property-style test across many seeds, not a single example. Determinism fixture with a juggle-heavy sequence replays to an identical hash, in-process and cross-process.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero **AND** the liveness property test passing across its full seed sweep.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate** — Story 8.1 owns the schema and grammar.
