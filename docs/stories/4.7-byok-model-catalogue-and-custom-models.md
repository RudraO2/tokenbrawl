# Story 4.7 — Bring your own model, and your own endpoint

As a visitor with an API key — free tier or paid, from a provider this repo has never heard of — I want to fight with the model I actually have, so that the picker is not a museum of whatever four models were current the week it was written.

## Why this exists, and what is wrong today

Story 4.6 offers four models from three providers, hard-listed in
`free-tier.config.json`. Measured against the owner's own provider dashboards
(`docs/reports/byok-provider-limits.md`, read it before starting), that list is
not merely thin — **two of its four entries cannot work**:

- `gemini-2.5-flash` has a **20-request daily cap**. A Match is up to 60 calls.
  It can never complete one. It is currently the default Google option.
- `gemini-2.5-pro` has **no free quota at all** on the measured account.
- Meanwhile **Gemma 4 31B / 26B on Google are 30 RPM and 14,400 RPD** — 240
  Matches a day, the strongest free option anywhere — and are not offered.
- **The committed Cerebras numbers are wrong**: the file says 30 RPM, the
  dashboard says **5 RPM**, and `llama3.1-8b` is not on the dashboard at all.

Beyond fixing that: models turn over weekly, OpenRouter alone carries hundreds,
and OpenAI and Anthropic have no free tier and so can never be reached by
extending an allowlist. A curated list is stale the day it lands.

## Acceptance criteria

**Given** the corrected data in `docs/reports/byok-provider-limits.md`, **When** the picker is shown, **Then** every offered model exists, and no model whose daily cap cannot cover one Match is offered as if it could.

**Given** any model in the picker, **When** it is shown, **Then** its free-tier RPM/RPD are shown with it, and a model that would take an unusual number of minutes to play a Match says so before the visitor starts rather than after.

**Given** a provider whose model travels in the request body, **When** the visitor types a model name that is on no list, **Then** the Match runs against it and the Command Log records that model verbatim.

**Given** a pasted key, **When** the visitor asks for their models, **Then** the picker is populated from that provider's own model endpoint, called with that visitor's key, sent to that provider's origin and to no other.

**Given** the Advanced panel, **When** a visitor supplies a base URL, a key and a model name, **Then** the Match runs against that endpoint, the key is sent there and to no other origin, and the endpoint is recorded in the Command Log per INV-6.

**Given** an Advanced endpoint, **When** it is entered, **Then** `https://` is required, the exact origin the key will be sent to is shown back to the visitor before the first request, and a plaintext URL is refused outright.

**Given** a model name the provider rejects as unknown or retired, **When** the Match is attempted, **Then** the visitor is told *that specific thing* — not a generic provider error — and no partially-recorded Match is produced.

**Given** tournament configuration, **When** anything in this story lands, **Then** it still refuses every non-free-tier endpoint and still refuses OpenRouter, unchanged.

## Scope

`packages/providers`: an OpenRouter adapter and a generic OpenAI-compatible
adapter (both are mostly configuration — the wire format is the one `groq.ts`
already speaks), plus a model-discovery call per provider. `apps/web`: the
model list with its limits, the custom-name field, the Advanced panel, and the
"fetch my models" path. `free-tier.config.json`: corrected and extended.

**Progressive disclosure.** The default view stays what 4.6 shipped: pick a
provider, pick a model, paste a key. Everything above is behind one `Advanced`
control. A visitor who wants the simple thing must not have to read about base
URLs to find it.

Verify the CORS preflight for every new endpoint the way 4.6 did, and append to
`docs/reports/byok-cors-preflight.md`.

## Invariants at risk

**INV-8 — read this whole section before touching `assertFreeTierEndpoint`.**

There are two separate cases and they have different answers.

1. **A custom model name.** For every provider except Google, the model travels
   in the request *body*; the URL is unchanged. The machine check is on
   endpoints, so this case does not touch INV-8 at all. Nothing to decide.

2. **A visitor-supplied base URL (Advanced).** This one genuinely cannot be on
   any allowlist — that is the point of it. The reading this story is built on,
   decided and twice reaffirmed by the project owner:

   > INV-8 is *"zero recurring cost"* — **this project's** cost. Tournament play
   > runs on this project's keys and is where a recurring cost could ever
   > appear, so the free-tier allowlist governs it absolutely and unchanged. A
   > BYOK Match runs on the visitor's own key and costs this project nothing,
   > whatever endpoint or model they choose. Refusing to let a visitor spend
   > their own money buys this project no protection from anything.

   So `assertFreeTierEndpoint` **stays exactly as strict as it is** and keeps
   guarding every tournament-configured client. The BYOK Advanced path takes a
   different constructor that never consults the allowlist, and the split must
   be visible in the code rather than implied — a boolean flag threaded into the
   existing factory is the wrong shape, because it makes one edit away from
   "just this once" in tournament configuration.

   `audit-invariants.sh` requires every `create*Client` factory to call
   `assertFreeTierEndpoint`. A new BYOK-only factory must either satisfy that
   sweep or the sweep must be narrowed *deliberately and with its reason
   written down* — do not let it fail silently, and do not rename a function to
   dodge a grep. If you cannot make that clean, **stop and escalate**.

**Security guard rails on the Advanced path** — these are acceptance criteria,
not suggestions. `https://` only, because a plaintext URL puts the key on the
wire in clear. The resolved origin shown back to the visitor before the first
request, because "type a URL, we send your key there" must never be a surprise.
The origin test from 4.6 extended, not replaced: the assertion becomes *only the
origin the visitor configured*, and it must still fail if any other host is
contacted.

**INV-6** — a custom model and a custom endpoint are recorded per call like any
other. Provenance does not weaken because the visitor supplied the values.

**AD-11** — still BYOK, still excluded from every rating. A paid model buys no
leaderboard row.

**AD-4** — no server. Discovery and the fight are both browser-to-provider.

## Test plan

Every offered model exists in the report's tables. A model whose RPD cannot cover
one Match is not offered as runnable. Custom model reaches the wire and the log
verbatim. Discovery populates from a recorded response and contacts one origin.
An Advanced endpoint sends the key to that origin and no other; `http://` is
refused; the origin is displayed before the first request. Unknown-model failure
is attributed and distinct from a generic provider error. Tournament config still
refuses every non-allowlisted endpoint and still refuses OpenRouter.

## Exit gate
