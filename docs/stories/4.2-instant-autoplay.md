# Story 4.2 — Instant autoplay

As a visitor arriving from a link, I want a fight already running when the page appears, so that I understand what this is before deciding whether to care.

## Acceptance criteria

**Given** a cold page load on a simulated 3G connection, **When** the page renders, **Then** the first animated frame appears within **2 seconds**.

**Given** a first-time visitor, **When** they arrive, **Then** no API key, no configuration and no click is required to reach a playing fight.

**Given** a Command Log whose reasoning payload is large, **When** the page loads, **Then** the fight still starts on time — reasoning is fetched from the sidecar lazily and playback never blocks on it.

**Given** the sidecar has not yet arrived, **When** a visitor hovers, **Then** the UI shows a loading state rather than an error or a blank.

## Scope

`apps/web`: bundling, asset budget, the sidecar split, and autoplay. If the log plus engine cannot meet the budget, split reasoning to a sidecar or truncate the hero replay — both are sanctioned by AD-10.

## Frozen contracts touched

`command-log.schema.json` `reasoningSidecar` — already present. Use it rather than inventing a second mechanism.

## Invariants at risk

- **INV-3** — a loading state must not leak how long any Agent thought.

## Architecture decisions that constrain this

- **AD-10** — reasoning is sheddable payload; playback never blocks on it.
- **AD-4** — small logs are what make this budget reachable.

## Test plan

Lighthouse or DevTools throttled-3G measurement of time to first animated frame. A test that playback starts with the sidecar deliberately delayed. Verify visually with the Chrome DevTools MCP.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero **AND** the measured 2-second budget met.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**.
