# Story 10.5 — The Ultimate sounds like one

As a visitor, I want the Ultimate to have its own audio cue, so that it reads even when I am not looking directly at it.

## Acceptance criteria

**Given** the three-bus audio layer from Story 9.6, **When** the Ultimate fires, **Then** it plays a distinct cue on the appropriate bus — never a louder reuse of the existing `sfx_hit_h` sample. An Ultimate that sounds like a heavy hit teaches a listener nothing.

**Given** the cue, **When** it is triggered, **Then** the trigger is the same frame-indexed event the cinematic uses (Story 10.4), so audio and picture cannot drift apart on a seek.

**Given** a browser with audio blocked, WebAudio absent, or the context never unlocked by a gesture, **When** the Ultimate fires, **Then** playback is silent and otherwise identical — the fail-soft rule `docs/ASSETS.md` already documents and `createAudioBus` already implements by returning `null`.

**Given** a visitor seeking the timeline across an Ultimate repeatedly, **When** they do, **Then** the cue does not stack or retrigger into a pile of overlapping sources.

**Given** any new audio file, **When** it lands, **Then** `docs/ASSETS.md` records its provenance and licence **in the same change** — never a later, separate commit. Existing audio in this repo is the author's own IP from the NextGen reference project and is recorded that way; a new cue follows the same rule.

**Given** any Match, **When** its Final-State Hash is compared before and after this story, **Then** it is unchanged (AD-15). Audio is never in the simulation path.

### The Scope section names the wrong file, and that is a story-scope slip, not a contract problem

Scope reads `apps/web/src/render/audio-bus.ts`. The cue table
(`DEFAULT_AUDIO_TUNING`) and the code that emits cues (`buildAudioTrack`) both
live in `render/audio.ts`; `audio-bus.ts` is the WebAudio sink, which resolves
*any* cue name to `/audio/<name>.mp3` and therefore needed **no change at all**.
So the work landed in `render/audio.ts` instead. Nothing in `docs/contracts/` is
involved and nothing was widened — recorded here and proceeded with, per the
escalation rule's own boundary.

### The trigger is Story 10.4's index, not a second reconstruction of it

`buildAudioTrack` already built a `firstClockOf` map — the first *clock* frame
presenting each film frame — so that a hit's SFX lands on the frame a freeze
starts and on none of its holds. The Ultimate's cue goes through that same map,
keyed on `CinematicEvent.filmIndex`, which is by definition the film frame
10.4's cinematic freeze opens on.

That is what makes AC2 true by construction. Audio and picture are not two
layers that agree; they are one index read twice. Verified end to end rather
than asserted: the Ultimate in `spectate-03` opens on **film frame 353**, the
juice track holds it across **clock 401–491**, and the cue sits on **clock
401** — the freeze's first frame, `frozen: false`, `cinematic.age === 0`, with
all 90 holds after it silent.

Two smaller decisions:

- **`tuning.ultimate` is its own key, not a fourth `sfx` entry.** `JuiceKind`
  grades *damage taken*; the cinematic fires on the caster's active phase
  whether or not the Ultimate connects. Widening `JuiceKind` would have pushed a
  non-damage event into the table that also drives hitstop, sparks and damage
  numbers.
- **Deliberately independent of `cinematic.freezeFrames`.** That number is the
  visual layer's off switch. A build that shortened or removed the freeze should
  still announce the Ultimate, so the audio layer's switch is its own field in
  its own table.

Two Ultimates opening on one film frame emit **one** cue, mirroring
`buildJuiceTrack`'s "one freeze, one caster". Two copies of one sample started
on one frame is a flam, not a bigger sound. No committed Command Log contains
simultaneous Ultimates, so that case is asserted against a track whose
`cinematics` stream is doubled by hand.

### The asset, and why AC5 is now mechanical

`sfx_special.mp3` copied byte-for-byte from the reference project's
`audio/sfx_special.mp3` — the same source and the same owner as the five cues
already in `apps/web/public/audio/`, and `docs/ASSETS.md`'s own "same owner"
section settles that. Its row landed **in this commit**, per AC5.

It is a genuinely different sample from `sfx_hit_h.mp3`, not a re-encode: MD5
`9bbc6a26…` against `c93bae72…`. AC1's point is that an Ultimate which sounds
like a heavy hit teaches a listener nothing, so "distinct" is checked at the
file, not only at the name.

**One gap found and closed while doing this.** `docs-discipline.test.ts` has
swept `public/sprites/` and `public/fonts/` against the provenance table since
Story 7.4. `public/audio/` had no such arm — audio landed in 9.7 without one —
so a sixth `.mp3` could have been dropped in with a fully green suite and no row
beside it. That is precisely the failure AC5 exists to prevent, and it was one
file away from happening. Added.

### What was deliberately *not* shipped

The reference plays **two** cues on its `ultimate` event: `sfx_special` on the
SFX bus and `vo_ultimate` on the voice bus (`screens.js:1308-1311`). Only the
SFX half is here. The voice table is deliberately KO-only — a voice line on
every big moment is how a fighting game becomes unlistenable — and a voice cue
would also pull a 90-frame duck over the music, which is a mix decision this
story was not asked to make. `vo_ultimate.mp3` exists in the source project if a
later story wants it; adding it is a row in `docs/ASSETS.md`, a key in
`tuning.voice`, and nothing else.

### Hash neutrality

`audio-neutrality.test.ts`'s existing cases run against the demo Match, which
contains no Ultimate — every one of them would have passed with
`tuning.ultimate` never emitted. So the claim is made against `spectate-03`, the
one committed Command Log containing an Ultimate, in the same shape
`cinematic-neutrality.test.ts` uses: hash first, run the whole painted playback
with a sink attached under two different tunings, then re-derive the hash from
the same log with a fresh environment. Identical both times, and the clock is
exactly as long with the cue as without it — the cue rides an existing frame
rather than adding one.
