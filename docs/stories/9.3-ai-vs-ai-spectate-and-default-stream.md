# Story 9.3 — AI-vs-AI Spectate and default stream

As a visitor, I want a fight already playing when I arrive with no click, and the ability to pick a specific matchup to watch, so that the site feels alive without anyone's compute running live for me.

**Does not depend on Epic 8.** A manifest walker over committed Command Logs does not care what dimensionality produced them.

## Acceptance criteria

**Given** no visitor action, **When** the page loads, **Then** a continuously looping carousel of precomputed Command Logs is already playing — the multi-Match extension of Story 4.2's instant-autoplay.

**Given** the manifest of committed logs, **When** one Match finishes, **Then** playback advances to the next entry automatically, with no gap and no server call.

**Given** a visitor picks a specific pairing from the leaderboard instead, **When** they select it, **Then** that specific precomputed Match plays — the same re-simulation-from-a-log mechanism (AD-4), just a chosen entry instead of the next one in sequence.

**Given** the carousel, **When** it runs for any length of time, **Then** the only network activity is static manifest and asset fetches — zero server calls, zero on-demand computation. Validates INV-8.

**Given** the transition from one looped Match to the next, **When** it happens, **Then** frame pacing stays constant across the boundary — INV-3 extended from "within a Match" to "across the carousel."

**Given** a visitor arriving mid-loop, **When** the page renders, **Then** they see a Match already in progress, not a blank or loading state.

## Scope

`apps/web`: a manifest walker built on the existing `player/clock.ts` mechanism, chaining multiple Command Logs instead of playing one. A static JSON manifest listing available logs, generated from whatever corpus exists — initially the scripted/demo replays, later real tournament output as it's produced.

## Frozen contracts touched

None.

## Invariants at risk

- **INV-8** — zero server calls, checked directly: nothing in this story's network activity is anything but a static fetch.
- **INV-3** — frame pacing constant across the Match-to-Match transition, not only within one Match.

## Architecture decisions that constrain this

- **AD-4** — replay is re-simulation from a log; this story is the multi-Match extension of that principle.
- **AD-17** — this story is AD-17's direct implementation: a manifest walk, never a computation trigger.

## Test plan

Test that the carousel advances to the next manifest entry automatically on completion, no gap. Network-activity test asserting only static-asset fetches occur during an extended run (extends the existing INV-8 audit). Frame-pacing test spanning a transition boundary between two Matches.
