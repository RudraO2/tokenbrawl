# Story 3.4 — The metering probe

As the developer, I want every Deployment tested for reporting honesty before it is ranked, so that a model that hides its reasoning tokens is never compared as if it did not.

## Acceptance criteria

**Given** a set of Deployments, **When** the probe runs, **Then** it correctly classifies at least one as `reports-reasoning` and at least one as `no-usage-reported`.

**Given** a Deployment that reports reasoning tokens on a plain call but drops them when reasoning is combined with structured output, **When** probed, **Then** it is classified as `reports-completion-only` — **the probe must exercise the combination, not the plain call alone.** This is a documented real behaviour, not a hypothetical.

**Given** any classification other than `reports-reasoning`, **When** results are generated, **Then** that Deployment appears only on the Reflex Track and never on the main leaderboard.

**Given** the probe results, **When** results are published, **Then** every exclusion appears with its reason. Silent omission is a defect.

## Scope

`packages/providers`: the probe, its classification logic, and persistence of results into `meteringProbe` on `DeploymentIdentity`.

## Frozen contracts touched

`docs/contracts/index.ts` `MeteringProbeResult` — the three values are fixed. Do not add a fourth without escalating.

## Invariants at risk

- **INV-5** — the whole story.
- **INV-4** — the probe itself must not send an effort parameter.

## Test plan

Fixture responses for each of the three classifications. A test that a `reports-completion-only` Deployment cannot reach main-leaderboard output. A test that the probe issues a structured-output call, not only a plain one.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**.
