# Story 3.1 — The Deployment agent and the identical scaffold

As the developer, I want one scaffold shared byte-for-byte by every model, so that prompt differences never masquerade as skill differences.

## Acceptance criteria

**Given** all configured Deployments, **When** their system prompts are compared, **Then** the Scaffold string is byte-identical across every one.

**Given** the codebase, **When** searched, **Then** no per-Deployment prompt override mechanism exists — no `promptOverride`, no `scaffoldFor`, no model-keyed prompt map.

**Given** an Observation from any Environment Adapter, **When** the prompt is assembled, **Then** assembly happens in core and the adapter contributes only the opaque `state` string.

**Given** Reflex Mode, **When** the prompt is built, **Then** it is the bare-Action variant and `max_tokens=8` is requested.

## Scope

`packages/core`: the Scaffold, the Action grammar, prompt assembly, and a `Deployment` implementation of the `Agent` port that delegates the HTTP call to a provider adapter. No specific provider yet.

## Frozen contracts touched

`docs/contracts/index.ts` `Agent`, `Prompt` — implemented, not modified.

## Invariants at risk

- **INV-7** — the whole story. The audit script greps for override mechanisms.
- **INV-4** — no reasoning-effort parameter may appear in the assembled request.

## Architecture decisions that constrain this

- **AD-7** — core owns the Scaffold; adapters own only state serialisation.
- **AD-6** — the agent reports raw usage; the Harness does the debit.

## Test plan

Byte-identity assertion across all configured Deployments. Grep-level test for override mechanisms. Reflex-Mode prompt shape. A test that adding a new provider requires no Scaffold change.

## Exit gate

`npm test` green **AND** `bash scripts/audit-invariants.sh` exiting zero. Reviewer opinion is never a gate.

## Standing rule

If this story appears to require a change to anything in `docs/contracts/`, **stop and escalate**. Never widen a frozen interface.
