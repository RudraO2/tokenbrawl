# Story 9.4 — Deterministic Deployment visual identity

As a visitor, I want two Deployments that share a model name but not an endpoint to actually look different, so that the "ranks Deployments, not models" claim is something I can see, not just read.

## Acceptance criteria

**Given** a Deployment's `(provider, endpoint, model)` triple, **When** it is hashed, **Then** colorway, glyph, and silhouette are derived from disjoint bit ranges of the digest.

**Given** two Deployments with the same model name but different endpoints, **When** both are rendered, **Then** they are visibly distinct.

**Given** the same triple, **When** hashed on any run or session, **Then** the identical visual identity results every time — idempotent, though this is a rendering property, not part of the Final-State Hash.

**Given** the three identity axes, **When** sampled across a range of inputs, **Then** they vary independently — no single bit change moving colorway, glyph, and silhouette together.

**Given** any Deployment's rendered fighter, **When** drawn, **Then** no vendor logo, brand mark, or character likeness of any provider appears anywhere.

## Scope

`apps/web`: a new visual-identity module consuming the existing hash primitive (`sha256.ts` in `env-fighter`, or `canonical-hash.ts` in `core` — reuse, do not add a new hash function), and its wiring into the existing renderer (`render/artist.ts`, `render/theme.ts`).

## Frozen contracts touched

None.

## Invariants at risk

None of INV-1..8 directly, but this story is the visible argument for INV-6 (Tokenbrawl ranks Deployments, not models) — worth keeping in mind during review even though no machine check enforces the *aesthetic* argument.

## Architecture decisions that constrain this

- **AD-15** — visual identity lives entirely in `apps/web`, never imports from or writes back into `packages/*`, and a Match's `finalStateHash` is provably identical whether or not this feature runs.

## Test plan

Unit tests: hash-to-identity is deterministic and idempotent. Two endpoints sharing a model name produce different identities. Independence check across a sampled input range — no two axes move in lockstep. Hash-neutrality test per AD-15: strip the visual-identity code path, re-run a Match, confirm `finalStateHash` is unchanged.

## Exit gate
